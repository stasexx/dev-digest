# Spec: PR Why + Risk Brief   |   Spec ID: SPEC-2026-10-18-pr-brief   |   Status: approved
Supersedes: none

## Problem & why

A reviewer often opens someone else's pull request "cold": they do not know why the change
exists, what in it is risky, or which file to read first. DevDigest already answers parts of
this, but in separate places: the **Intent** layer (L03) states the PR's purpose and scope,
**Smart Diff** (L03) groups changed files by role, and **Blast Radius** (L04) shows what else
the change can reach. Nothing combines them, and nothing says "these are the risks" or
"start reading here".

The **PR Brief** puts these facts into one block on the Overview tab and adds three parts
written by a model in **one** structured call:

- **Summary**: what the PR does and why.
- **Risk areas**: specific risks, each tied to a file.
- **Review focus — read these first**: an ordered list of `file:line — reason`. Clicking an
  item opens Files changed at that file and line.

The model gets **facts that are already computed** (intent, blast-radius summary and caller
files, diff statistics with Smart Diff roles, PR description, linked issue, attached specs).
It never gets the code of the diff hunks. One sentence for the demo: *the model reasons
over cheap, deterministic, already-verified facts instead of re-reading the raw diff, so the
brief stays inside a fixed token budget, costs one call, and cannot cite a file that the PR
or its blast map does not contain.*

The brief is cached per PR and tied to the head commit SHA it was generated for. Reopening
or reloading the page shows the same brief without a new model call, and a new commit marks
the brief as stale.

## Goals / Non-goals

- Goal: On the Overview tab, a **PR Brief** block that offers **Generate brief** while no
  brief exists. Once a brief exists, the block shows the summary, Risk areas and Review focus,
  with the existing Intent and Blast radius cards next to it.
- Goal: Generate the brief with **exactly one** structured model call. The model comes from
  the Settings entry **Risk Brief** (`risk_brief`) and is never hard-coded. The output is
  validated by the shared contract.
- Goal: Build the model input only from pre-computed facts, each with a documented
  provenance. The input stays within a fixed budget of **8,000 estimated tokens**, with a
  deterministic order for what gets cut first.
- Goal: **Ground** the output. Drop every risk reference and review-focus item whose file is
  in neither the PR's changed files nor the blast map used for that generation.
- Goal: **Cache** the brief in the existing `pr_brief(pr_id, json)` store, with the head SHA
  inside the JSON. A stale brief is flagged after a new commit, and a refresh control
  regenerates it.
- Goal: **Degrade gracefully.** When Intent, Blast radius, specs or the linked issue are
  unavailable, the brief is still generated and says in deterministic UI text (not model
  prose) which data was missing.
- Goal: Make clicking a Review focus item (and, for P3, a risk) open **Files changed**
  (`?tab=diff`) on that file and scroll to that line. A file outside this PR's diff shows
  "File not in this PR's diff".
- Goal (P3): A verdict banner above the summary, built from the latest review (verdict,
  findings and blockers count, PR score). Risks expand to show their explanation. A skeleton
  shows while generating. All strings come from `client/messages/en/brief.json`.
- Goal: Add `summary` and `review_focus[{ file, line, reason }]` to the `PrBrief` contract in
  **both** copies of `brief.ts`.
- Non-goal: **Sending diff hunk bodies to the model.** No added, removed or context lines, no
  text after hunk headers, and no repository file contents other than attached spec
  documents.
- Non-goal: **Any second model or embedding call** during generation. The brief does not
  compute Intent, does not ask for an LLM blast summary, and makes no per-file summaries.
- Non-goal: **Automatic generation.** Nothing generates a brief on page open, on a new
  commit, or after a review run. Generation happens only through Generate or Refresh.
- Non-goal: Brief history or versioning. One cached brief per PR, and regenerating
  overwrites it.
- Non-goal: Prior PRs ("Prior PRs touching these files", L04 P3) as an input or a section of
  the brief.
- Non-goal: Line-level grounding (rejecting a review-focus line that falls outside the
  changed hunks). Grounding is file-level only (see Resolved questions). The UI falls back to the
  file when a line is not rendered.
- Non-goal: Posting the brief to GitHub, letting users edit it, or streaming generation
  progress over SSE.
- Non-goal: Changes to the review pipeline, reviewer-core, `groundFindings()`, the Intent
  layer's own behaviour (including the Intent card's existing lazy compute), or the Blast
  radius / Smart Diff endpoints.
- Non-goal: New storage for the cache, or a new Settings entry. `pr_brief` and `risk_brief`
  already exist.
- Non-goal: Coordinating "generation in progress" across several server processes. The app
  runs as one process.

## User stories

- US-1: As a reviewer, I want to see a PR Brief block with a **Generate brief** button on the
  Overview tab when no brief exists yet, so that I know a brief is available and how to get it.
- US-2: As a reviewer, I want to generate the brief and see a short summary (what and why),
  Risk areas and Review focus, with Intent and Blast radius next to them, so that I understand
  the PR before reading the diff.
- US-3: As a reviewer, I want each risk to show a title, a severity and the file it concerns,
  and (P3) to expand it for the explanation and click it to open the file, so that I can
  judge and locate each risk.
- US-4: As a reviewer, I want Review focus as an ordered `file:line — reason` list that opens
  Files changed at that file (P1) and line (P2), so that I start reading in the right place.
- US-5: As a reviewer, I want a page reload to show the same brief immediately, without a new
  generation, so that I do not wait for it or pay for it twice.
- US-6: As a reviewer, I want a refresh control that regenerates the brief, so that I can
  update it after changes or when it is stale.
- US-7: As a reviewer, I want to see when the brief was generated for an older commit than
  the PR's current head, so that I do not trust stale risks.
- US-8: As a reviewer, I want the brief to say which inputs were missing (for example Intent
  not computed, or Blast radius index unavailable), so that I know how much to trust it.
- US-9: As the workspace owner, I want generation to make exactly one model call, using the
  model I picked for Risk Brief in Settings, within a known input budget, without diff code,
  and visible in the logs, so that cost and data exposure stay predictable and checkable.
- US-10: As a security-minded reviewer, I want the brief never to reference files that are
  not in the PR or its blast map, and PR text never to steer the model, so that a malicious PR
  body cannot plant fake guidance.
- US-11 (P3): As a reviewer, I want the latest review's verdict and PR score in a banner above
  the summary, so that I see the review outcome and the brief together.
- US-12: As the course mentor, I want the feature PR to carry this spec, the plan, the plan
  verifier's report and a demo video, committed in pipeline order, so that I can check the
  SDD process and not just the code.

## Provenance of every input

Each input is read from an **existing** source of truth. The brief adds no new way to compute
any of them.

| Input | Source of truth (existing) | Enters the prompt | Never enters the prompt | When absent |
|---|---|---|---|---|
| PR title, PR totals | The PR as `GET /pulls/:id` serves it (`title`, `additions`, `deletions`, `files_count`) | Title; totals of files and lines added/removed | — | Always present |
| PR description | `GET /pulls/:id` → `body` (the persisted PR body) | Body text, capped (see Budget) | — | Recorded `description: empty`. Normal, not "missing" |
| Diff stats | `GET /pulls/:id` → `files[]` (`path`, `additions`, `deletions`); Smart Diff `GET /pulls/:id/smart-diff` → role per file (`core / tests / wiring / docs / boilerplate`) and `finding_lines` of the latest review | Per file: path, role, `+a −d`, its **new-side changed line ranges as numbers only** (taken from the hunk headers' ranges), and the latest-review finding line numbers | Patch text: hunk bodies, and the context text after a hunk header | A file Smart Diff does not know gets role `core` (the Files changed tab's existing fallback). An empty PR yields an empty list |
| Intent | Stored PR intent: the `pr_intent` table, read the way the review run already reads it (`getIntent(prId)`). **Read only. Never computed by the brief.** | `intent`, `in_scope[]`, `out_of_scope[]` | — | Recorded missing (`intent`, reason `not_computed`) |
| Blast radius | The same index-only blast lookup that serves `GET /pulls/:id/blast` (`BlastRadiusResponse`) | `summary`, `stats`, `changed_symbols[]` (name, file, kind), callers as `symbol → file:line` grouped per changed symbol (rank order), `endpoints_affected`, `crons_affected`, and the degraded flag and reason | `facts_by_file` beyond the above, `limits`, internal ranks | Lookup error, or degraded with zero changed symbols and zero callers → recorded missing (`blast`, with reason). Degraded but with data → recorded `partial` with reason |
| Linked issue | The rule PR detail already uses for `PrDetail.linked_issue`: the first `#N` reference in the PR body, fetched from GitHub (`number`, `title`, `state`, `body`). Best effort | Number, title, state, body (capped) | — | No reference → `none` (normal). Referenced but GitHub unavailable or fetch failed → `unavailable` (listed as missing) |
| Attached specs | Project Context Folder documents attached to agents: the de-duplicated union of `attached_doc_paths` of every **enabled** agent in the workspace and of each such agent's **enabled** skills. Read fresh from the PR repository's clone through the existing clone path guard | For each document: path and full text, capped as one section (see Budget) | Any file that is not attached | None attached, clone absent, or all paths unreadable → recorded missing (`specs`, with reason). Each unreadable path is recorded individually |

Mandated existing capabilities: the model call uses the existing structured-completion
capability (`completeStructured`), which validates against a Zod schema and re-prompts on
invalid JSON. The model is resolved per workspace for the `risk_brief` feature
(`resolveFeatureModel(container, workspaceId, 'risk_brief')`).

## Input budget

- **Unit:** *estimated tokens* = `ceil(characters / 4)`. This is the heuristic the repo already
  uses for the intent classifier's token estimates and for Project Context document
  estimates.
- **Measured over:** the full assembled model input, meaning the system message plus the user
  message. The structured-output schema or tool definition that the provider adds is outside
  this estimate. Provider-reported `tokens_in` is recorded separately and may differ.
- **Budget:** **8,000 estimated tokens** in total, allocated as follows. Unused allowance is
  **not** moved to other sections.

| # cut order | Section | Allowance (est. tokens) | How it is shortened when over its allowance |
|---|---|---|---|
| never | Fixed: instructions, PR title, PR totals, intent, blast summary line + stats, missing-inputs list | ≤ 1,200 (reserved) | Never shortened |
| 1 (cut first) | Attached specs | 2,400 | Whole documents in attach order. The first document that does not fit is truncated, ending with `…[truncated]`. Later documents are omitted, and their paths are recorded |
| 2 | Blast detail (changed symbols, callers `file:line`, endpoints, crons) | 1,000 | Callers kept in rank order. The tail is replaced by one line `+K more callers` |
| 3 | Linked issue | 600 | Body tail truncated, ending with `…[truncated]` |
| 4 | PR description | 1,000 | Tail truncated, ending with `…[truncated]` |
| 5 (cut last) | Per-file list | 1,800 | Files ordered by role `core → wiring → tests → docs → boilerplate`, then by churn (`a + d`) descending. Files that do not fit collapse into one line per role, `+K files (+A −D)` |

If, after these caps, the total still exceeds 8,000 (possible only when the fixed content
overflows its reserve), whole capped sections are **removed** in the cut order above, until
the total fits. If the fixed content alone exceeds the budget, generation is refused before
any model call.

## Acceptance criteria (EARS)

Priority tags trace each criterion to the homework's acceptance tiers: **[P1]** blocking,
**[P2]**, **[P3]**. **[ext]** marks robustness criteria this spec adds to close gaps it found.

### A. PR Brief block and its states (Overview)

- AC-1 [P1]: WHEN a user opens the Overview tab of a PR that has no cached brief, the system
  **shall** render a "PR Brief" block containing a **Generate brief** button and the
  "brief not available yet" empty-state text, and **shall not** issue any model call.
  _(observable: component test with GET returning `brief: null` shows the button and the empty text; a server test with a call-counting mock provider records 0 model calls for GET)_
- AC-2 [P1]: WHEN the user activates **Generate brief**, the system **shall** request
  generation for that PR. On success it **shall** render the brief's summary, the Risk areas
  section and the Review focus section inside the PR Brief block.
  _(observable: component test — click → POST issued → summary, Risk areas and Review focus rendered from the response)_
- AC-3 [P3]: WHILE a generation for the PR is in progress and no brief is displayed, the PR
  Brief block **shall** show a skeleton in place of the summary, Risk areas and Review focus,
  and the block **shall** be marked busy for assistive technology.
  _(observable: component test with a pending POST shows skeleton elements and `aria-busy="true"`)_
- AC-4 [P1]: The Overview tab **shall** show the existing Intent card and Blast radius card
  next to the brief content inside the PR Brief area, and **shall** keep the existing PR
  description section.
  _(observable: Overview render test — PR Brief block, Intent card, Blast radius card and description all present; manual check against proto1.png)_
- AC-5 [P1]: WHERE the displayed brief records one or more missing inputs, the PR Brief block
  **shall** show a notice that names each missing input (Intent, Blast radius, Attached specs,
  Linked issue) and its reason. The notice **shall** be derived from the brief's recorded
  inputs, not from model text.
  _(observable: component test with `missing_inputs` = intent + blast renders both names and reasons; the notice is absent when `missing_inputs` is empty)_
- AC-6 [P2]: WHILE the displayed brief is stale, the PR Brief block **shall** keep showing the
  brief, together with a stale notice that names the short SHA the brief was generated for,
  the PR's current short SHA, and a Regenerate control.
  _(observable: component test with `stale: true` shows both short SHAs and the control, and the brief content is still rendered)_
- AC-7 [P1]: WHILE a brief is displayed, the PR Brief block **shall** offer a refresh control.
  WHEN the user activates it, the system **shall** generate a new brief and, on success,
  replace the displayed brief with the new one.
  _(observable: component test — click refresh → POST issued → new summary rendered; e2e: two consecutive generations yield two model calls)_
- AC-8 [ext]: WHILE a regeneration is in progress and a brief is displayed, the system
  **shall** keep the current brief visible, show the refresh control in a loading state, and
  disable both Generate and refresh until the request settles.
  _(observable: component test with a pending POST — old summary still visible, controls disabled)_
- AC-9 [ext]: IF a generation request fails, THEN the PR Brief block **shall** show an error
  message naming the failure category (model not configured / model output invalid or
  provider error / generation already running / rate limited / input over budget) with a
  retry control, and **shall** leave any previously displayed brief unchanged.
  _(observable: component test per error code — the message for that category renders and the previous brief remains)_

### B. Brief contents rendering

- AC-10 [P1]: The system **shall** render each risk with its title, its severity
  (`high | medium | low`), and at least its first grounded file reference as `path` or
  `path:line[-line]`. Severity **shall** be conveyed by icon colour **and** by a text or
  accessible label.
  _(observable: component test — each risk row shows title + file ref; the severity label is queryable by text or aria-label)_
- AC-11 [P3]: WHEN the user expands a risk, the system **shall** show that risk's explanation.
  Risks **shall** be collapsed by default, and the expand control **shall** expose its
  expanded state.
  _(observable: component test — explanation hidden initially, visible after toggle; `aria-expanded` flips)_
- AC-12 [ext]: The system **shall** pick each risk's icon from its `kind`, and **shall** use a
  generic risk icon for any `kind` it does not recognise.
  _(observable: component test — unknown kind renders the fallback icon without error)_
- AC-13 [P1]: The system **shall** render the Review focus items as an ordered list, in the
  order stored in the brief. Each item **shall** show `file:line` and its reason, and the
  section header **shall** show the number of items.
  _(observable: component test — rendered order equals `review_focus` order; header count equals its length)_
- AC-14 [P1]: WHERE the brief has zero risks, the Risk areas section **shall** show the
  existing "no notable risks" message. WHERE it has zero Review focus items, that section
  **shall** show a "no review focus items" message.
  _(observable: component test with empty arrays shows both messages)_
- AC-15 [P3]: WHERE the PR has at least one completed review, the PR Brief block **shall** show
  a verdict banner above the summary. The banner shows the latest review's verdict, findings
  count, blockers count and PR score, with the brief's summary as its text. WHERE the PR has
  no review, the block **shall** show the summary without verdict or score.
  _(observable: component test with/without reviews; "latest" = the newest review of kind `review`)_
- AC-16 [P3]: The PR Brief block **shall** take every user-facing string from the `brief`
  message namespace (`client/messages/en/brief.json`). It reuses `block.intent`,
  `block.blast`, `block.risks`, `noRisks`, `unavailable` and `unavailableHint` for their
  purposes and adds any new strings to the same namespace. No user-facing string is written
  directly in a component.
  _(observable: grep finds no literal English in the brief components; tests resolve strings through the `brief` namespace)_
- AC-17 [ext]: WHERE the brief carries generation metadata, the PR Brief block **shall**
  display the model used, the generation time, and the token counts in → out. It **shall**
  also show the cost when the cost is known.
  _(observable: component test renders `8.2K→1.3K`-style token text and `$0.014`-style cost from metadata; cost is hidden when null)_
- AC-18 [ext]: The system **shall** render all brief text (summary, titles, explanations,
  reasons, paths) as plain text, never as HTML.
  _(observable: component test — a summary containing `<img onerror=…>` renders as literal text and creates no element)_

### C. Navigation from the brief to Files changed

- AC-19 [P1]: WHEN the user activates a Review focus item whose file is among the PR's changed
  files, the system **shall**:
  1. Switch the PR page to the Files changed tab, using a URL that carries the tab, the file
     and the line.
  2. Expand the role group and the file card that contain the file, even if either is
     collapsed by default.
  3. Scroll the file into view below the sticky PR header.
  The same **shall** happen WHEN the page is loaded directly with such a URL.
  _(observable: component/e2e test — click item → URL has `tab=diff`, `file`, `line`; the target file card is expanded and its header is in the viewport, including for a file in the default-collapsed boilerplate group)_
- AC-20 [P2]: WHEN Files changed opens with a target line that is rendered in the target file's
  diff (matched on its new-side line number), the system **shall** scroll that line into view
  and highlight it visually.
  _(observable: component/e2e test — the target line element is in the viewport and carries the highlight state)_
- AC-21 [ext]: IF the target line is not rendered (outside the changed hunks, or the file has
  no patch text), THEN the system **shall** scroll to the file header and **shall not** show an
  error.
  _(observable: component test with a line outside every hunk → file header in view, no error UI)_
- AC-22 [P3]: WHEN the user activates a risk, the system **shall** navigate as in AC-19 and AC-20
  to the risk's first grounded file reference, using the reference's first line when it
  carries one.
  _(observable: component test — click risk with ref `a.ts:12-18` → URL `file=a.ts&line=12`)_
- AC-23 [P3]: WHEN the user activates a Review focus item or risk whose file is **not** among the
  PR's changed files (it is in the blast map only), the system **shall** stay on Overview and
  show the short message "File not in this PR's diff" next to that item. WHEN Files changed is
  opened with a target file that is not among the PR's changed files, it **shall** show the
  same message instead of scrolling.
  _(observable: component tests for both entry points)_
- AC-24 [ext]: The Files changed tab **shall** honour the target file and line in both Smart
  order and Original order, including when Smart Diff is unavailable. It **shall** act on the
  file parameter only when it exactly matches a changed file path, and on the line parameter
  only when it is a positive integer. Any other value is ignored, without error.
  _(observable: component tests — smart and original order both scroll; `line=-3` / `line=abc` / unknown file do not throw)_

### D. Generation inputs and provenance

- AC-25 [P1]: WHEN a brief is generated, the system **shall** assemble the model input only
  from the inputs listed in the *Provenance* table, each taken from the source given there.
  _(observable: unit test of the assembled input with fixtures for every source — each section's content traces to its fixture; no other content beyond fixed instructions)_
- AC-26 [P2]: The assembled model input **shall not** contain any line of any diff hunk body
  (added, removed or context), the text after any hunk header, or the contents of any
  repository file other than the attached spec documents.
  _(observable: unit test — sentinel strings placed in patch bodies, hunk-header context and a non-attached file never appear in the assembled input)_
- AC-27 [P1]: The system **shall** read Intent only from the stored PR intent and **shall not**
  compute Intent during brief generation. IF no stored intent exists, THEN the system **shall**
  record Intent as missing (reason `not_computed`) and continue.
  _(observable: test with no stored intent — 1 model call total (the brief's), intent recorded missing)_
- AC-28 [P1]: The system **shall** take blast radius from the same index-only lookup that
  serves `GET /pulls/:id/blast`. IF that lookup fails, or returns degraded with zero changed
  symbols and zero callers, THEN blast **shall** be recorded missing with its reason. IF it
  returns degraded with data, THEN blast **shall** be recorded `partial` with its reason and
  included together with its degraded note.
  _(observable: unit tests for error / empty-degraded / partial / full lookups)_
- AC-29 [P1]: The system **shall** derive the linked issue with the same rule that PR detail
  uses for `linked_issue`. IF the PR body references no issue, THEN the linked issue **shall**
  be recorded `none` and not listed as missing. IF an issue is referenced but cannot be
  fetched (no GitHub token, network or API error), THEN it **shall** be recorded `unavailable`
  and listed as missing, and generation **shall** continue.
  _(observable: unit tests for no-ref / fetched / fetch-failed with a mock GitHub client)_
- AC-30 [P1]: The system **shall** take attached specs as the de-duplicated union of document
  paths attached to the workspace's enabled agents and to those agents' enabled skills. The
  order **shall** be deterministic: agents by creation time, each agent's paths in attach
  order, then its enabled skills in skill order, with the first occurrence kept. Each document
  **shall** be read fresh from the PR repository's clone through the existing clone path
  guard. A path that is missing, unreadable or refused by the guard **shall** be skipped and
  recorded. IF none are attached, the clone is absent, or every path is skipped, THEN specs
  **shall** be recorded missing with the reason.
  _(observable: unit tests — agent + skill overlap deduped; a stale path recorded; a traversal path refused; disabled agent/skill contributes nothing)_
- AC-31 [P1]: WHEN one or more inputs are missing, the system **shall** still generate the
  brief, and **shall** include in the model input a "missing inputs" section naming them.
  _(observable: test with intent + blast + specs all missing → generation succeeds; assembled input contains the missing-inputs section)_
- AC-32 [ext]: The brief generation request **shall not** call any model-backed endpoint or
  capability other than its own single structured call. It makes no Intent computation, no
  LLM blast summary, no embeddings and no per-file summaries.
  _(observable: call-counting mock provider + embedder record exactly 1 structured call and 0 embeddings per POST)_

### E. Input budget

- AC-33 [P2]: The total model input (system + user message) of every generation **shall** be
  at most **8,000 estimated tokens**, where estimated tokens = `ceil(characters / 4)`.
  _(observable: unit test with oversized fixtures — recorded and recomputed estimate ≤ 8,000)_
- AC-34 [P2]: WHEN a section exceeds its allowance in the *Input budget* table, the system
  **shall** shorten that section by that section's rule, ending any truncated text with
  `…[truncated]`.
  _(observable: unit tests per section — over-long description truncated with marker; 3rd spec omitted and its path recorded; 300-file PR collapses to per-role aggregate lines; callers tail replaced by `+K more callers`)_
- AC-35 [P2]: IF after section caps the total still exceeds 8,000 estimated tokens, THEN the
  system **shall** remove whole capped sections in the cut order (attached specs → blast
  detail → linked issue → PR description → per-file list) until the total fits, and **shall
  never** shorten or remove the fixed content.
  _(observable: unit test with oversized fixed content — removal follows the stated order)_
- AC-36 [ext]: IF the fixed content alone exceeds 8,000 estimated tokens, THEN the system
  **shall** refuse the generation with an "input over budget" error and **shall not** make a
  model call.
  _(observable: unit test — error code returned, 0 model calls, cache unchanged)_
- AC-37 [P2]: For every generation, the system **shall** record in the brief record and in the
  generation log:
  - the input token estimate and the budget;
  - which sections were truncated or removed;
  - which spec paths were read, missing, truncated or omitted.
  _(observable: record and log entry contain these fields with values matching the fixture)_

### F. Model call

- AC-38 [P2]: WHEN a brief is generated, the system **shall** issue exactly one structured
  model call. A schema-repair re-prompt made inside that call counts as an attempt of that
  call and is recorded in `attempts`. The system **shall** issue no model call when it serves
  a cached brief.
  _(observable: call-counting mock — exactly 1 structured call per POST, 0 per GET; `attempts` recorded)_
- AC-39 [P2]: The system **shall** resolve the provider and model for that call from the
  workspace's **Risk Brief** (`risk_brief`) setting, using the registry default when the
  workspace has not chosen one, and **shall** record the provider and model in the brief.
  _(observable: test — set `feature_models.risk_brief` → the call uses that provider/model and the record shows it; no model literal in the brief feature code)_
- AC-40 [P2]: The model output **shall** be validated against the brief output contract
  `{ summary, risks[], review_focus[] }` within the structured call. IF it is still invalid
  after the allowed repair attempts, THEN the generation **shall** fail (AC-9) and nothing
  **shall** be cached.
  _(observable: mock returning invalid JSON on all attempts → error response, `pr_brief` row unchanged)_
- AC-41 [P1]: The model instructions **shall** require all of the following:
  - a summary of at most 3 sentences saying what the PR changes and why;
  - for each risk: a kind, title, explanation, severity and at least one file reference;
  - Review focus items in recommended reading order, each with a file, a new-side line and a
    reason;
  - citing only files that appear in the provided PR file list or blast map;
  - treating every PR-derived text as data, not instructions.
  _(observable: unit test asserts the assembled system message contains each instruction)_

### G. Grounding (no invented paths)

- AC-42 [P1]: WHEN the model output is received, the system **shall** normalise each risk file
  reference: strip a trailing `:line` or `:start-end` suffix and a leading `./` or `/`. It
  **shall** remove each reference whose path does not exactly (case-sensitively) equal a path
  in the generation's allowed set. The allowed set is the PR's changed files plus the blast
  map's changed-symbol files and caller files. A risk whose references are all removed
  **shall** be dropped.
  _(observable: unit test — risk with one real + one fabricated ref keeps only the real one; risk with only fabricated refs is dropped; `./src/a.ts:3` matches `src/a.ts`)_
- AC-43 [P1]: WHEN the model output is received, the system **shall** drop each Review focus
  item whose normalised file is not in the allowed set.
  _(observable: unit test — fabricated-path item dropped, real PR file and blast caller file kept)_
- AC-44 [P1]: WHERE blast radius is missing for the generation, the allowed set **shall** be
  the PR's changed files only.
  _(observable: unit test — with blast missing, an item on a caller-only file is dropped)_
- AC-45 [ext]: After grounding, the system **shall**:
  - de-duplicate Review focus items that have the same file and line, keeping the first;
  - keep the model's order;
  - keep at most 8 risks and 8 Review focus items;
  - record how many risks, risk references and Review focus items were dropped by grounding
    and by the cap.
  _(observable: unit test with 12 items incl. duplicates → 8 kept in order, counts recorded)_
- AC-46 [P1]: The brief the system persists and returns **shall** contain only grounded risks
  and grounded Review focus items.
  _(observable: integration test — model mock returns fabricated paths; the GET response contains none of them)_

### H. Cache and staleness

- AC-47 [P1]: WHEN a generation succeeds, the system **shall** persist the complete brief
  record, including the head SHA of the PR state used for the generation, as that PR's single
  cached brief in `pr_brief`, replacing any previous one.
  _(observable: integration test — row JSON holds `head_sha`; a second generation overwrites the first)_
- AC-48 [P1]: WHEN a client requests the brief, the system **shall** return the cached brief

- AC-49 [P1]: WHEN the Overview tab loads for a PR with a cached brief, including on a full

  generation request.
  _(observable: e2e — generate, reload, brief visible; network log shows GET only, no POST; model-call count unchanged)_
- AC-50 [P2]: WHEN the cached brief's head SHA differs from the PR's current head SHA, the
  system **shall** return the brief with `stale: true` and **shall not** regenerate it

  _(observable: integration test — change stored head SHA → GET returns `stale: true`, 0 model calls)_
- AC-51 [P2]: WHEN a PR detail refresh observes a head SHA different from the stored one, the

- AC-52 [ext]: IF the cached JSON does not validate against the current brief record contract,

## Edge cases

- No brief yet → Generate CTA, no model call. → AC-1
- Intent never computed, or the Intent model is failing → brief is generated, and Intent is
  listed as missing. → AC-27, AC-31, AC-5
- The Intent card on Overview is still lazily computing intent when the user clicks Generate
  → the brief sees no stored intent and records it missing. The user can regenerate later.
  → AC-27; **accepted: race, no handling beyond the missing notice**
- Blast index absent, failed, flag off or repo too large (empty degraded result) → blast
  missing with reason. Degraded with data → `partial`. Lookup throws → missing. → AC-28, AC-5
- No GitHub token / offline → linked issue `unavailable`. PR files and body come from the
  persisted PR state. → AC-29
- Empty PR description → recorded `empty`, not listed as missing. → AC-25 (Provenance)
- PR with zero changed files → generation proceeds, grounding leaves no items, and both
  empty-state messages show. → AC-14, AC-42, AC-43
- PR with more than 100 files: the GitHub file listing is capped, so the persisted file list
  may be incomplete → a real file beyond the cap is dropped by grounding. → **accepted: no
  handling (pre-existing PR-detail limit)**
- Very long description, issue body, or spec document; very many files or callers → section
  caps and the cut order apply. → AC-34, AC-35
- Fixed content alone over budget (pathological title or intent) → refused before the model
  call. → AC-36
- Attached spec deleted, unreadable, non-UTF-8, symlink escape or `..` traversal → skipped and
  recorded, or refused by the guard. → AC-30
- Clone absent → specs missing (`clone_unavailable`). → AC-30
- A spec document is itself changed by the PR → the clone's working-tree (default-branch)
  version is used, not the PR head version. → **accepted: no handling**
- An attached path exists in agents' lists but not in this repo (agents are workspace-wide,
  paths are repo-relative) → skipped and recorded. → AC-30
- Model invents a path, or cites a path with `./` or a `:line` suffix → normalised, then
  dropped if not allowed. → AC-42, AC-43
- Model cites a path that differs only in case, or the pre-rename path of a renamed file →
  dropped (exact match). → AC-42; **accepted: renames not followed**
- Model returns invalid JSON or a schema violation → repaired inside the one call, otherwise
  an error and nothing cached. → AC-40, AC-9, AC-53
- Model returns more than 8 items, or duplicate focus items → capped and de-duplicated, with
  counts recorded. → AC-45
- Review focus line beyond the end of the file or outside the changed hunks → the UI falls
  back to the file header. → AC-21; **accepted: no line-level grounding** (Resolved questions)
- Provider key for the Risk Brief model is missing → configuration error, no call. → AC-57
- Provider timeout or 5xx → error, previous brief kept. → AC-9, AC-53
- Double-click on Generate, or two tabs generating at once → one generation, one conflict
  error. → AC-8, AC-54
- Page reload during generation → skeleton plus re-check until done. → AC-55
- New commit lands during generation → brief stored with the SHA it used, so it shows as
  stale on the next GET. → AC-47, AC-50
- Stored PR head SHA lags behind the head SHA GitHub reports in PR detail → persisted on the
  detail refresh. → AC-51
- Cached JSON from an older contract version, or corrupted → treated as no brief. → AC-52
- PR id from another workspace → not found. → AC-56
- Prompt injection in the PR title, body, issue, spec text, file names or symbol names → the
  text is wrapped as untrusted, and grounding keeps the output to real files.
  → AC-41, AC-42, AC-43, *Untrusted inputs*
- Model output containing HTML or markup → rendered as plain text. → AC-18
- Clicking an item whose file is in the blast map only → "File not in this PR's diff", stay on
  Overview. → AC-23
- Deep link to an unknown file, or with an invalid line → ignored, or the same message.
  → AC-23, AC-24
- Target file is in a default-collapsed group (docs, boilerplate) or a large auto-collapsed
  card → expanded before scrolling. → AC-19
- Smart Diff fails → Original order, and the deep link still works. → AC-24
- Binary file, or file without patch text → scroll to the file header. → AC-21
- A review run finishes after the brief was generated → the banner shows the new latest
  review, and the brief summary is unchanged. → AC-15; **accepted: brief not invalidated by
  reviews**
- Provider-reported `tokens_in` above 8,000 (because of schema/tool overhead and tokenizer
  differences) → the budget applies to the estimate, and both figures are recorded. → AC-33,
  AC-37; **accepted**
- Stored intent derived from an older head commit → used as stored. → **accepted: intent is
  per PR, not per SHA**
- The Risk Brief model setting changes after a brief was generated → the brief keeps showing
  the model it was made with and is not marked stale. → AC-39; **accepted**
- Server restarts mid-generation → nothing cached, `generating` resets, and the user retries.
  → AC-53; **accepted: no recovery**

## Non-functional

- **Input budget:** ≤ 8,000 estimated tokens (`ceil(chars/4)`) per generation (AC-33).
- **Model calls:** exactly 1 structured call per generation and 0 per read (AC-38). Internal
  schema repair is capped by the provider's existing limit of at most 3 attempts in total,
  each bounded by the provider's existing per-attempt timeout.
- **Latency:**
  - `GET /pulls/:id/brief` p95 ≤ 300 ms on the local stack. It is a database read only, with
    no model and no GitHub call.
  - Pre-model input assembly for `POST` p95 ≤ 5 s for a PR with ≤ 100 files and ≤ 5 attached
    documents. This includes the best-effort linked-issue fetch; a slow GitHub fetch degrades
    to `unavailable`.
- **Rate limit:** generation is limited to 10 requests per minute (AC-60).
- **Security:**
  - Workspace-scoped access on both endpoints (AC-56).
  - Untrusted wrapping of every PR-derived text in the prompt (*Untrusted inputs*).
  - Grounded output (AC-42–AC-46).
  - Plain-text rendering (AC-18).
  - Validated deep-link parameters (AC-24).
  - Error bodies free of raw model output and prompt or spec text (AC-59).
  - Info-level logs carry sizes and counts only. Prompt text may appear only at debug level,
    as the intent classifier already does.
- **Accessibility:** WCAG 2.1 AA for the PR Brief block:
  - Review focus items and risks are reachable and operable by keyboard (Enter/Space), with a
    visible focus ring.
  - Severity is not conveyed by colour alone (AC-10).
  - The expand state is exposed (AC-11).
  - The skeleton is marked busy (AC-3).
  - The missing-inputs, stale and "File not in this PR's diff" notices are announced through
    a polite live region.
- **i18n:** every string comes from the `brief` namespace (AC-16).

## Cross-module interactions

The feature spans **server** and **client**, plus an optional **e2e** flow. **reviewer-core**
is not changed. Only its existing untrusted-wrapping helper is reused, through the server's
existing re-export.

**Server:**

- Owns a new brief capability with two operations:
  - read the cached brief (`GET /pulls/:id/brief`);
  - generate a new one (`POST /pulls/:id/brief`).
- Reads (all workspace-scoped):
  - the PR, its persisted changed files and body;
  - the stored intent;
  - the blast radius from the repo-intel index;
  - Smart Diff roles and the latest review's finding lines;
  - the enabled agents' and skills' attached document paths, with the documents' text from
    the repository clone (path-guarded);
  - the workspace's `risk_brief` model setting.
- Fetches the linked issue from GitHub (best effort).
- Calls the LLM provider once.
- Writes the brief record into `pr_brief`.
- In the existing **pulls** capability: the PR detail refresh persists the head SHA it
  observes (AC-51).

**Client:**

- The Overview tab gains the PR Brief block: state machine, banner, sections and
  navigation.
- The block reads the brief and triggers generation through the two endpoints, the latest
  review through the existing reviews read, and PR files through the existing PR detail.
- The Files changed tab honours a target file and line (deep link) and the "not in diff"
  notice.
- The client copy of the shared contract changes together with the server copy.

**Failure contract:**

- Every input source is **fail-soft**. A failure is recorded as missing, partial or
  unavailable, and generation continues.
- Only three conditions fail a generation: a missing PR (not found), an over-budget fixed
  input (refused before the call), and a failure of the single model call (configuration,
  provider or schema).
- A failed generation never changes the cache.
- Reading never fails because the cached JSON is bad (AC-52).

```mermaid
sequenceDiagram
    participant UI as client (Overview / Files changed)
    participant API as server (brief capability)
    participant DB as Postgres (PR, files, pr_intent, agents/skills, settings, pr_brief)
    participant RI as repo-intel index (blast) + Smart Diff (roles)
    participant FS as repo clone (attached specs, path-guarded)
    participant GH as GitHub (linked issue, best-effort)
    participant LLM as LLM provider (risk_brief model)

    UI->>API: GET /pulls/:id/brief
    API->>DB: PR (workspace-scoped) + pr_brief.json
    API-->>UI: { brief | null, stale, current_head_sha, generating }  (0 model calls)

    UI->>API: POST /pulls/:id/brief  (Generate / Refresh)
    API->>API: reject if a generation for this PR is in flight (409)
    API->>DB: PR title/body/totals, changed files, stored intent, attached paths, risk_brief setting
    API->>RI: blast radius (index-only) + roles / finding lines (deterministic)
    API->>FS: read attached docs (skip + record unreadable)
    API->>GH: linked issue (best-effort; failure → unavailable)
    API->>API: assemble facts, wrap untrusted, apply section caps + cut order (≤ 8,000 est. tokens)
    API->>LLM: ONE structured call → { summary, risks[], review_focus[] } (schema-validated)
    LLM-->>API: output (or error → no cache write)
    API->>API: ground against PR files ∪ blast files, dedupe, cap, record drops
    API->>DB: upsert pr_brief.json (incl. head_sha, inputs, generation metadata)
    API-->>UI: { brief, stale: false, current_head_sha, generating: false }
    UI->>UI: Review focus click → ?tab=diff&file=…&line=… → expand + scroll + highlight
```

## Contracts

Shapes only: fields, direction, optionality. Existing shapes were verified in the shared
`brief.ts`:

- `Intent { intent; in_scope[]; out_of_scope[] }`
- `Risk { kind: string; title; explanation; severity: high|medium|low; file_refs: string[] }`
- `Risks { risks: Risk[] }`
- `PrBrief { intent: Intent; blast: BlastRadius; risks: Risks; history: PrHistory }`

`PrBrief` currently has no runtime consumer; the only use is a type re-export on the client.

- **ReviewFocusItem** (new, model → server → client): `{ file: string` (repo-relative path; must
  be in the generation's allowed set after grounding); `line: integer ≥ 1` (new-side, that
  is head, line number); `reason: string` (non-empty) `}`.
- **Risk.file_refs format** (existing field, meaning now pinned): each entry is `path`,
  `path:line`, or `path:start-end`. Grounding uses the path part only (AC-42).
- **PrBrief** (changed, in **both** `brief.ts` copies):
  - **added** `summary: string` (non-empty);
  - **added** `review_focus: ReviewFocusItem[]`;
  - `risks: Risks` is unchanged;
  - `intent` becomes **nullable** (null = intent missing for this generation; otherwise the
    snapshot that was used);
  - `blast` becomes **nullable** (null = blast missing; otherwise the snapshot of the core
    `BlastRadius` fields that was used);
  - `history` becomes **optional** (prior PRs are a non-goal; v1 omits it).

  The nullability changes were accepted (see Resolved questions).
- **BriefModelOutput** (model → server; the schema of the single structured call):
  `{ summary: string; risks: Risk[]; review_focus: ReviewFocusItem[] }`. The flat `risks[]`
  is wrapped into `Risks` when the record is stored.
- **PrBriefRecord** (persisted as `pr_brief.json`; server → client) = `PrBrief` plus:
  - `pr_id`
  - `head_sha` — SHA of the PR state used
  - `generated_at` — ISO timestamp
  - `model: { provider; model }`
  - `missing_inputs: { input: 'intent'|'blast'|'specs'|'linked_issue'; reason: string }[]`
  - `inputs`, which holds:
    - `intent: present|missing`
    - `blast: present|partial|missing`, with `blast_reason`
    - `description: present|empty`
    - `linked_issue: present|none|unavailable`
    - `specs: { read[]; missing[]; truncated[]; omitted[] }`
    - `files_total`
    - `files_listed`
  - `generation`, which holds:
    - `input_tokens_estimate`
    - `input_budget_tokens` (8,000)
    - `truncated_sections[]`
    - `removed_sections[]`
    - `attempts`
    - `tokens_in`
    - `tokens_out`
    - `cost_usd | null`
    - `duration_ms`
    - `dropped: { risks; risk_refs; review_focus; over_cap }`
- **PrBriefResponse** (server → client, for both GET and successful POST):
  - `brief: PrBriefRecord | null`
  - `stale: boolean` (`brief.head_sha ≠ current_head_sha`; false when brief is null)
  - `current_head_sha: string`
  - `generating: boolean`
- **Endpoints:**
  - `GET /pulls/:id/brief` → `PrBriefResponse`. Never calls a model or GitHub.
  - `POST /pulls/:id/brief` (no body) → `PrBriefResponse` after generation. Synchronous.
  - Both are workspace-scoped. Both responses are validated against the contract at the
    boundary (AC-62).
- **Errors** (existing envelope `{ error: { code; message; details? } }`, never carrying raw
  model output, prompt or spec text):
  - not found (404);
  - generation in progress (409);
  - rate limited (429);
  - model not configured (configuration error);
  - model failed or output invalid (upstream error);
  - input over budget (refused, no call).

  The exact code strings are left to the planner.
- **Files changed deep link** (client URL contract):
  `/repos/:repoId/pulls/:number?tab=diff&file=<url-encoded repo-relative path>&line=<positive int>`.
  `line` is optional. Both parameters are untrusted input (AC-24).

## Untrusted inputs

**Yes.** The feature puts third-party text into a model prompt and renders model output:

- Data placed in the prompt as **untrusted**, each piece wrapped with the existing untrusted
  fence and its source label:
  - PR title, PR description, linked issue title and body;
  - attached spec document text;
  - changed file paths and blast symbol names, file paths and endpoint/cron names;
  - stored intent text (model-derived from untrusted text).

  The system message states that all of it is data, not instructions (AC-41). Diff hunk
  bodies are never included (AC-26).
- **Model output is untrusted too.** Its file references are accepted only after grounding
  against the deterministic allowed set (AC-42–AC-46). All brief text is rendered as plain
  text (AC-18). Navigation targets are only in-app deep links built from grounded paths. No
  model-supplied URL is ever followed.
- **Deep-link parameters** (`file`, `line`) are untrusted URL input. They are acted on only
  when they match a changed file exactly and the line is a positive integer (AC-24).
- **Spec documents** are read only through the existing clone path guard, which blocks
  traversal and symlink escape (AC-30).
- reviewer-core's `groundFindings()` gate is not involved: the brief produces no review
  findings. The brief's own file-level grounding plays the same role for its output.

## Resolved questions

Every question raised while drafting was answered by the human on 2026-10-18, who accepted
each proposed default as written. The criteria above already encode these decisions; none of
them is open.

- **Attached specs scope.** Which agents' attached documents feed the brief?
  Decision (human, 2026-10-18): accepted default — the union over all enabled agents in the
  workspace and their enabled skills, de-duplicated and in deterministic order (AC-30).
- **Budget numbers.** What total budget and section split, and is unused allowance reassigned?
  Decision (human, 2026-10-18): accepted default — 8,000 estimated tokens with the section
  allowances in the *Input budget* table, and no reassignment of unused allowance.
- **Stale behaviour.** Mark stale, or auto-regenerate after a new commit?
  Decision (human, 2026-10-18): accepted default — mark stale and offer Regenerate; never
  auto-regenerate (AC-50).
- **What counts as "one model call".**
  Decision (human, 2026-10-18): accepted default — one structured-call invocation; its internal
  schema-repair re-prompts count as recorded attempts of that call (AC-38).
- **Where Review focus line numbers come from.**
  Decision (human, 2026-10-18): accepted default — numeric new-side changed line ranges (no
  hunk-header context text) plus latest-review finding lines, which do not count as diff code
  (Provenance, AC-26).
- **Line-level grounding.**
  Decision (human, 2026-10-18): accepted default — file-level grounding only; the UI falls back
  to the file header when the line is not rendered (AC-21).
- **Linked issue rule.**
  Decision (human, 2026-10-18): accepted default — the same rule PR detail uses (the first
  `#N` reference in the body, fetched from GitHub, best effort) (AC-29).
- **`PrBrief` field changes beyond the two additions.**
  Decision (human, 2026-10-18): accepted default — `intent` and `blast` become nullable, and
  `history` becomes optional and is omitted in v1 (Contracts).
- **Item caps.**
  Decision (human, 2026-10-18): accepted default — at most 8 risks and 8 Review focus items
  after grounding, in model order (AC-45).
- **Clicking a blast-map-only file.**
  Decision (human, 2026-10-18): accepted default — stay on Overview and show "File not in this
  PR's diff" (AC-23).
- **Concurrent generation.**
  Decision (human, 2026-10-18): accepted default — a second POST while one is in flight gets a
  409 conflict (AC-54).
- **Persisting the head SHA on PR detail refresh.**
  Decision (human, 2026-10-18): accepted default — in scope; the PR detail refresh persists the
  observed head SHA (AC-51).
- **UX copy.**
  Decision (human, 2026-10-18): accepted default — the `block.risks` value becomes "Risk
