# Cross-model review of docs/plans/pr-brief.md

- **Reviewer:** Codex CLI 0.153.4, model `gpt-6-astra` (OpenAI family). The plan's author, `implementation-planner`, ran on Claude Opus.
- **Date:** 2026-10-18.
- **Input:** the approved spec, the plan and 10 key source files, inlined with line numbers. Codex's bwrap sandbox cannot run commands on this host (`Failed RTM_NEWADDR: Operation not permitted`), so the files were passed as text and Codex ran no tools.
- **Verdict:** REVISE. The plan was sent back to `implementation-planner`; the resolution of each finding is recorded below the review.

## Review (verbatim)

The plan traces all 68 ACs, but several implementation steps contradict those requirements. Findings below use only the supplied text.

1. **AC-37/58: logging omits required data and failed calls.** `docs/plans/pr-brief.md:719` omits spec-path read/missing/truncated/omitted metadata from both log entries. Lines 708 and 794–795 explicitly log model calls only on success, so failed, billable invocations disappear from the call count. Log each structured invocation once, including its outcome and available metadata; never log prompt or output contents at info level.

2. **AC-16: the proposed banner violates the namespace requirement.** The plan acknowledges that `VerdictBanner` uses `prReview` but mandates reusing it unchanged (`docs/plans/pr-brief.md:828–832,889–890`). It also displays an English server error directly (857–858). Provide brief-owned translations, including a localized configuration message with provider interpolation; assign ownership of any necessary shared-component change.

3. **AC-33/34: section fitting is underspecified for oversized non-body content.** T2 truncates only callers in blast detail and only the linked issue’s body (`docs/plans/pr-brief.md:457–461`). Changed symbols, endpoints, crons, or the issue title alone can exceed their section allowances. Define deterministic handling and tests for these cases, including fence/heading/aggregate overhead. The final 8,000-token check does not by itself enforce individual section caps.

4. **Repair attempts create an unresolved budget boundary.** The existing adapter appends invalid assistant output and repair instructions before resending (`server/src/adapters/llm/anthropic.ts:140–155`). T2 measures only the initial system/user input (`docs/plans/pr-brief.md:496`). Explicitly establish whether AC-33 covers only that initial input or every repair request; if the latter, the current adapter cannot guarantee it without additional budget handling. Internal repairs remain permitted under the spec’s definition of one structured call.

5. **AC-47: capturing `pull.headSha` does not guarantee a matching fact snapshot.** T4 reads the pull before gathering facts (`docs/plans/pr-brief.md:701–716`), while Smart Diff independently rereads PR files (`server/src/modules/smart-diff/service.ts:20–25`) and Blast independently rereads changed paths (`server/src/modules/blast/service.ts:33–36`). A concurrent detail refresh can mix an old SHA with newer files. Specify a consistent read strategy or detect head changes during assembly and retry assembly before the single model invocation.

6. **AC-54/55: the successful response can retain `generating: true`.** T4 returns `get()` from inside the lock’s `try/finally` (`docs/plans/pr-brief.md:703–720`), while `get()` reads that lock (698). The result depends on whether the return is awaited and when the flag is evaluated. Release explicitly before constructing the successful response. Add a test asserting POST returns `generating:false`; the proposed client stops polling whenever a brief exists (652).

7. **AC-19/20: scrolling has a DOM-readiness race.** T7’s effect is keyed only by target and effective order, while groups open in a separate effect (`docs/plans/pr-brief.md:910–920`). On asynchronous Smart Diff resolution or a target change within a collapsed group, the target may not exist when scrolling runs. Trigger scrolling after expansion commits, and mark the target handled only after successful lookup. Test delayed data and same-tab target changes.

8. **Task interfaces need clearer ownership.** T1 freezes shared types/constants, but T2/T3/T4 may require corrections to them; no integration owner is designated. T6’s namespace fix also needs T5-owned message changes. Add a controlled handoff for shared-contract/message fixes and run final verification after all parallel writers finish.

9. **Verification overclaims what is proved.** The plan accepts nine server typecheck errors despite AC-61 saying both typechecks pass (`docs/plans/pr-brief.md:422–424`; spec:483–484). Record an explicit accepted exception or fix the baseline. V-GROUND fetches fresh PR/blast state rather than the generation snapshot (plan:1122–1132), so it cannot prove generation-time grounding.

The proposed single `completeStructured` invocation, stored-intent read, numeric-only diff projection, and file-level grounding otherwise align with the spec. The supplied Blast and Smart Diff implementations support the no-additional-model-call assumption. Adapter helpers, diff-loader signatures, path guards, and several client components are not inlined, so their claimed compatibility cannot be independently verified here.

**Verdict: REVISE — Top 3 must-fix items: complete invocation logging; explicit section/repair budget handling; consistent SHA-and-facts snapshot.**

## Resolution

`implementation-planner` revised `docs/plans/pr-brief.md` in place on 2026-10-18. The structure and all 68 AC mappings are kept.

1. **Logging.** There is a new "Logging contract" under Architecture changes. Every structured invocation, success or failure, gets exactly one `brief: model call` entry with `outcome`/`errorCategory`, `specs.{read,missing,truncated,omitted}` and `maxRetries`. Refusals log `brief: refused`. Prompt and output text appear only at debug. T4 runGeneration step 5 and its tests gained success, invalid-output and timeout cases plus a no-content check; AC-37/AC-58 rows and V-LOG were updated.
2. **Banner i18n.** T6 now owns one additive optional `labels` prop on the shared `VerdictBanner` (owned path `VerdictBanner/**`, with a test that the default output is unchanged). T5 adds the `brief.verdict.*` keys and an ICU `errors.modelNotConfigured` with `{provider}`. T4 sends `details: { setting, provider }` for that code only. T6 never renders server text, and its tests load only the `brief` namespace with an `onError` spy. See also Codebase verification #15, the Error codes table and the AC-16 row.
3. **Section fitting.** T2 budget.ts gained `clip` and a deterministic `fitLines` that counts heading, fence and aggregate overhead. Each section cap is asserted, not only the 8k total. Blast detail now has per-category `+K more` aggregates for symbols, callers, endpoints and crons, and the issue title is clipped. T1 constants add `BRIEF_MAX_*_CHARS`. The T2 tests gained a "section cap invariant" with pathological symbols, endpoints, crons, title, paths and labels, a forced-overhead drop case and a determinism case. The AC-34 row was updated.
4. **Repair budget.** Resolved interpretation I-1 states that AC-33 covers the initial system + user request. Repairs are bounded by `maxRetries: 2` and `maxTokens: 4096`, with the real `tokens_in` and `attempts` recorded. This is in T2 (doc comment), T4 step 5 and the T4 test "repair bounds passed"; the AC-33 row and V-GEN were updated.
5. **Consistent snapshot.** T3 now reads `pr_files` once per snapshot. It feeds the pure Smart Diff and Blast steps (`buildSmartDiff` + `selectLatestReviewFindings`; facade + `toBlastRadius`) plus a new row-based `diffFromPrFileRows`, and exports `filesFingerprint`. It has parity tests and owns `reviews/diff-loader.ts`. T4 re-checks the head SHA and fingerprint after assembly, reassembles once (`BRIEF_MAX_SNAPSHOT_RETRIES`) and records the snapshot SHA. The T4 test is "head moved during assembly → reassembled once"; see also Codebase verification #18 and the AC-47 row.
6. **Lock release.** In T4 `generate`, the lock is released in `finally` around `runGeneration`, and the response is built after that. The T4 test "POST returns generating:false" covers success and failure; the AC-54 row, V-GEN (prints `generating`) and the brief.it POST case were updated.
7. **Scroll race.** In T7, the scroll is triggered by the target FileCard's own post-commit effect (`onTargetReady`), after its group and card are open. The target is marked handled only after a successful lookup, and a new key re-arms it. New tests cover delayed Smart Diff data, a same-tab target change and handled-once.
8. **Ownership and final gate.** Execution mode gained a "Handoff for frozen interfaces" section. T1 owns contracts, types and constants; T5 owns messages, hooks and link utils. Change requests go through serial `T1-fix` / `T5-fix` runs between batches. A new read-only **T10 integration gate** runs after all writers (T4, T8 and any fixes) with an ownership-mapping check, and T9 now depends on T10. The batch table, mermaid DAG and red-flags were updated.
9. **Typecheck and V-GROUND.** Exception E-1 is recorded under Resolved interpretations: 9 pre-existing TS18048 errors, accepted for AC-61. T0 captures `docs/reports/pr-brief/typecheck-baseline.txt`, and V-TYPECHECK diffs against it (used in T1–T4, T10 and Testing strategy). The AC-61 row was updated. V-GROUND now rebuilds the allowed set only from the brief's own snapshot: a new `inputs.changed_files` (T1, Rec-3) plus the stored `blast`.
